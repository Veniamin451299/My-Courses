Этот пример — классическая задача HTTP CLIENT из курса learnyounode. На первый взгляд код кажется простым, но под капотом он использует мощную концепцию NodeJS — потоки данных (Streams) и события (Events).

Давайте разберем каждую строчку, а затем детально ответим, почему обработчик ошибок .on('error', ...) вызывается дважды.

# Разбор кода по строчкам
1. const http = require('http'); — Подключаем встроенный модуль Node.js для работы с сетью.
2. const req = process.argv[2]; — Берем URL-адрес из аргументов командной строки (например, http://example.com).
3. http.get(req, res => { ... }) — Метод отправляет асинхронный GET-запрос на указанный URL. Когда удаленный сервер отвечает и присылает первые заголовки ответа, Node.js вызывает callback-функцию и передает в нее объект ответа — res.

Внутри callback-функции res представляет собой поток чтения (Readable Stream). Данные от сервера не приходят мгновенно и целиком — они текут маленькими кусочками (чанками):
- res.setEncoding('utf8'); — Говорит потоку автоматически превращать сырые буферы байтов (Buffer) в понятный человеку текст формата UTF-8. Без этой строки в консоли вывелись бы наборы шестнадцатеричных чисел.
- res.on('data', data => { console.log(data); }); — Подписываемся на событие 'data'. Как только из интернета прилетает очередной кусочек текста, срабатывает этот callback и выводит его в консоль.
- res.on('error', console.error) — Обработчик ошибок для потока ответа (Response).

## Почему метод on('error') вызывается дважды?
Два вызова .on('error', ...) нужны потому, что они слушают абсолютно разные типы ошибок на разных этапах запроса. В сетевом взаимодействии есть две принципиально разные сущности: сам Запрос (клиент пытается достучаться до сервера) и Ответ (сервер уже общается с клиентом).

Давайте посмотрим на структуру кода еще раз, визуально разделив эти обработчики:
```javascript
http.get(req, res => {
    // === 1. ВНУТРЕННИЙ ОБРАБОТЧИК (Ошибки ОТВЕТА) ===
    res.on('error', console.error); 
})
// === 2. ВНЕШНИЙ ОБРАБОТЧИК (Ошибки ЗАПРОСА) ===
.on('error', console.error);
```

1. Внешний .on('error', ...) (в самом конце)
Это обработчик ошибок самого объекта запроса (ClientRequest).
- Когда он срабатывает: До того, как сервер вообще успел вам что-то ответить. Ошибка происходит на этапе установления соединения.
- Примеры:
    - Вы передали несуществующий домен (например, http://asdfghjkl-fake-domain.com). Произойдет ошибка ENOTFOUND (сервер не найден).
    - У вас отключен интернет.
    - Сервер «упал», закрыл порт или заблокирован брандмауэром (ECONNREFUSED).
2. Внутренний res.on('error', ...) (внутри callback)
Это обработчик ошибок объекта ответа (IncomingMessage). Сюда управление дойдет только в том случае, если внешний запрос успешно связался с сервером, и сервер начал присылать данные.

- Когда он срабатывает: В процессе скачивания тела ответа (пока капают события 'data').
- Примеры:
    - Соединение оборвалось прямо посреди скачивания большого файла или страницы (например, провайдер оборвал связь).
    - Сервер прислал некорректные или поврежденные данные, которые нарушают протокол HTTP.
## Резюме
Если убрать внешний обработчик, программа намертво упадет (Crash) с системной ошибкой при любой опечатке в URL. Если убрать внутренний обработчик, программа упадет, если интернет пропадет прямо в секунду скачивания текста. Node.js заставляет нас разделять эти зоны ответственности, так как это два разных объекта (Request и Response).
