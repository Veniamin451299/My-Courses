# Часть 1: Поднимаем базу данных локально

Раз у тебя уже установлен PostgreSQL, нам нужно создать чистую базу данных для проекта. Это можно сделать через графическую утилиту **pgAdmin** (она идет в комплекте с Postgres) либо через консоль.

## **Шаг 1. Создание БД через pgAdmin (или консоль):**
1. Открой **pgAdmin** и подключись к своему серверу (потребуется пароль, который ты указывал при установке Postgres).
2. Нажми правой кнопкой мыши на раздел `Databases` ➡️ `Create` ➡️ `Database...`.
3. Назови базу данных: `task_manager_db` и нажми **Save**.

## **Шаг 2. Формирование строки подключения (Connection String):**  
Prisma ORM должна знать, где искать твою базу. Строка подключения имеет строгий формат. Открой свой файл `.env` и добавь туда переменную `DATABASE_URL`:
```env
DATABASE_URL="postgresql://ИМЯ_ПОЛЬЗОВАТЕЛЯ:ПАРОЛЬ@localhost:5432/task_manager_db?schema=public"
```

- **ИМЯ_ПОЛЬЗОВАТЕЛЯ**: по умолчанию в Postgres это `postgres`.
- **ПАРОЛЬ**: твой секретный пароль от Postgres.
- **5432**: стандартный порт PostgreSQL.

# Часть 2: Краткий экскурс в SQL (Что нужно знать бэкендеру)

Поскольку мы используем ORM (Prisma), она сама будет писать SQL-код под капотом. Но ты обязан понимать базовые команды, так как Prisma — это просто обертка над ними.

В SQL есть 4 главные операции (они полностью соответствуют концепции CRUD в REST API):
1. **`SELECT`** (Найти/Прочитать) — аналог `GET`.
    - _Сырой SQL:_ `SELECT * FROM "Task";` (Выбрать все задачи).
    - _Сырой SQL с фильтром:_ `SELECT * FROM "Task" WHERE id = 1;`.
2. **`INSERT INTO`** (Создать/Вставить) — аналог `POST`.
    - _Сырой SQL:_ `INSERT INTO "Task" (title, description) VALUES ('Купить молоко', 'В магазине у дома');`.
3. **`UPDATE`** (Изменить) — аналог `PUT/PATCH`.
    - _Сырой SQL:_ `UPDATE "Task" SET "isCompleted" = true WHERE id = 1;`.
4. **`DELETE`** (Удалить) — аналог `DELETE`.
    - _Сырой SQL:_ `DELETE FROM "Task" WHERE id = 1;`.

# Часть 3: Изучаем ORM Prisma

**Prisma ORM** — это мост между твоим JavaScript-кодом и реляционной базой данных. Вместо написания текстовых SQL-запросов, ты будешь вызывать красивые методы JavaScript.

## Шаг 1. Инициализация Prisma в проекте

Открой терминал в корне твоего проекта и выполни две команды:
```bash
# 1. Устанавливаем Prisma как инструмент разработки
npm install prisma --save-dev

# 2. Инициализируем настройки Prisma для PostgreSQL
npx prisma init --datasource-provider postgresql
```

После этого в твоем проекте появится новая папка `prisma`, а внутри неё — файл **`schema.prisma`**. Это самое главное место.

## Шаг 2. Описание схемы данных (Моделирование)

Открой файл `prisma/schema.prisma`. Тебе нужно описать нашу таблицу задач. Удали оттуда лишние примеры (если они будут) и добавь описание нашей модели `Task`:

```prisma
datasource db {
  provider = "postgresql"
}

generator client {
  provider = "prisma-client-js"
}

// 🌟 Вот так описывается таблица в Prisma:
model Task {
  id          Int      @id @default(autoincrement()) // Числовой ID, который сам увеличивается (+1)
  title       String                                // Строковое обязательное поле
  description String?                               // Знак вопроса означает "необязательное поле" (может быть null)
  isCompleted Boolean  @default(false)              // Булево поле, по умолчанию false
  createdAt   DateTime @default(now())              // Автоматически ставит текущую дату создания
}
```

Ссылку на базу данных указываем в конфигурационном файле Prisma, если ее еще там нет:
```
// This file was generated by Prisma, and assumes you have installed the following:
// npm install --save-dev prisma dotenv

import "dotenv/config";
import { defineConfig, env } from "prisma/config";


export default defineConfig({
  schema: "prisma/schema.prisma",
  migrations: {
    path: "prisma/migrations",
  },

  datasource: {
    url: env("DATABASE_URL"), // <-- Здесь
  },
});
```

## Шаг 3. Что такое миграции? (Команда `prisma migrate`)

Когда ты описал модель в файле `schema.prisma`, в самой базе данных Postgres таблицы еще нет. Чтобы превратить этот текст в реальную физическую таблицу, нужно запустить **миграцию**.

Выполни в терминале команду:
```bash
%% Если не установлены необходимые пакеты конфигурации - выполняем: %%
npm install dotenv @prisma/config

npx prisma generate

npx prisma migrate dev --name init_tasks
```

### **Что произойдет под капотом:**
1. Prisma сравнит твой файл `schema.prisma` с реальной базой данных.
2. Сама сгенерирует SQL-скрипт создания таблицы.
3. Выполнит его в твоем локальном Postgres.
4. Создаст в твоем проекте специальный программный клиент (Prisma Client), через который мы будем делать запросы.

# Часть 4: Синтаксис запросов Prisma (Шпаргалка для Сервисов)

Чтобы делать запросы, мы импортируем `PrismaClient`. Вот как твои старые методы из `toDoService.js`, работавшие с массивом, переписываются на реальную БД:

```javascript
const { PrismaClient } = require('@prisma/client');
const prisma = new PrismaClient();

// 1. Получить все записи (Аналог SELECT * FROM)
const tasks = await prisma.task.findMany();

// 2. Получить одну запись по ID (Аналог SELECT WHERE id = ...)
const task = await prisma.task.findUnique({
    where: { id: Number(id) }
});

// 3. Создать запись (Аналог INSERT INTO)
const newTask = await prisma.task.create({
    data: {
        title: "Купить хлеб",
        description: "Ржаной"
    }
});

// 4. Обновить запись (Аналог UPDATE)
const updatedTask = await prisma.task.update({
    where: { id: Number(id) },
    data: { isCompleted: true }
});

// 5. Удалить запись (Аналог DELETE)
const deletedTask = await prisma.task.delete({
    where: { id: Number(id) }
});
```

_⚠️ Важнейший нюанс:_ Все методы Prisma являются **асинхронными** (возвращают Promise). Поэтому в слое `Services` перед вызовами методов Prisma обязательно нужно писать ключевое слово **`await`**, а сами функции делать **`async`**.
