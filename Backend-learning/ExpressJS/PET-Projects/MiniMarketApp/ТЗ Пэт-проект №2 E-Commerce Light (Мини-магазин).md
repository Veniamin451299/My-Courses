Мы пишем REST API для интернет-магазина. Здесь у нас появится новая концепция: **связи между разными таблицами**, управление корзиной и подсчет сумм на бэкенде.

# 1. Архитектура Базы Данных (Prisma Schema)

Тебе нужно будет описать 3 сущности (таблицы):
1. **User (Пользователь)**: `id`, `email`, `password`, `role` (строка, по умолчанию `'customer'`, но может быть и `'admin'`).
2. **Product (Товар)**: `id`, `title`, `description`, `price` (Int или Float), `stock` (Int — количество товара на складе).
3. **CartItem (Элемент корзины)**: связь «многие ко многим» через промежуточную таблицу. Элемент содержит: `id`, `userId`, `productId`, `quantity` (Int — сколько штук этого товара пользователь положил в корзину).

---

# 2. Список Эндпоинтов (Роутов), которые нужно реализовать

Блок 1: Авторизация (`/api/auth`)
- `POST /register` и `POST /login` — используй свой готовый идеальный каркас с `bcrypt` и `jwt`.

Блок 2: Каталог товаров (`/api/products`) — Доступен ВСЕМ (Public)
- `GET /` — Получить список всех товаров. **(🌟 Сюда обязательно внедряем Redis-кэш!)**.
- `GET /:id` — Получить один товар по замаскированному ID.
- `POST /` — Создать товар (Доступно **ТОЛЬКО** пользователям с ролью `'admin'`). _Подсказка: тут тебе пригодится твоя кастомная мидлварь проверки ролей вроде `checkAdmin`!_

Блок 3: Корзина (`/api/cart`) — Приватный (Private, нужен JWT)
- `GET /` — Посмотреть свою корзину. Сервер должен вернуть список товаров в корзине текущего пользователя и **автоматически посчитать итоговую сумму заказа (`totalPrice`)**.
- `POST /` — Добавить товар в корзину. Клиент присылает `{ productId: "хэш_строка", quantity: 2 }`.
    - _Логика безопасности:_ Сервер должен расшифровать ID, проверить через Prisma, есть ли такой товар и хватает ли его на складе (`stock`).
- `DELETE /:id` — Удалить товар из корзины (или уменьшить количество).

---

# 3. Обязательные требования:
- **Zod-валидация**: проверка цены (не может быть отрицательной), количества (минимум 1).
- **Безопасность**: маскирование всех ID (`Hashids`), защита `helmet`, санитизация строк от XSS.
- **Инвалидация кэша**: если админ создаёт новый товар через `POST /api/products`, кэш каталога в Redis должен мгновенно очищаться.
- **Тесты (Jest)**: в конце напишем тесты на проверку корзины и роли админа.

---

# С чего начать?

Весь безопасный каркас (`app.js`, `env.js`, `errorResponse.js`, `hashid.js`) у тебя уже есть. Твой первый шаг:

1. Создай новую папку для проекта (например, `mini-market-api`).
2. Перенеси туда каркас.
3. Обнови файл `schema.prisma`, описав три новые модели (`User`, `Product`, `CartItem`) и запусти миграцию `npx prisma migrate dev`.

Последовательность команд:
bash

# 1. Создаем папку и инициализируем npm
mkdir my-project
cd my-project
npm init -y           # создает package.json

# 2. Устанавливаем базовые зависимости
npm install express dotenv helmet

# 3. Устанавливаем dev-зависимости
npm install -D nodemon jest supertest

# 4. (Опционально) Устанавливаем TypeScript
npm install -D typescript @types/node
npx tsc --init
