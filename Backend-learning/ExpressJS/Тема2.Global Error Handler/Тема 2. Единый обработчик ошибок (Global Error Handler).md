Обрати внимание на свой роут: в нем снова появился блок `try/catch`. Если у тебя на сервере будет 50 роутов, тебе придется писать `try/catch` 50 раз. Это нарушает принцип DRY (не повторяйся) и засоряет код.

В Express.js эту проблему решает специальный тип мидлвари — **Error Handling Middleware**. Она всегда пишется в самом низу файла (после всех роутов) и отличается от обычной мидлвари тем, что принимает строго **4 аргумента**: `(err, req, res, next)`.

Как только Express видит функцию с 4 аргументами, он понимает: «О, это глобальный спасатель от багов!».
# Как это работает?

Если внутри любого роута что-то ломается, тебе больше не нужно писать `try/catch` для отправки ответа. Ты можешь просто поймать ошибку и передать её в функцию `next(error)`. Если в `next()` передать любой аргумент, Express мгновенно бросает выполнение обычных роутов и летит в самый низ файла к глобальному обработчику ошибок.

# Твое практическое задание:

Давай перепишем твой сервер так, чтобы избавиться от `try/catch` внутри роута.

1. Оставь роут `GET /secret`.
2. Внутри роута вместо `try/catch` принудительно вызови ошибку, чтобы протестировать систему. Например:
```javascript
    app.get('/secret', checkAdmin, (req, res, next) => {
        // Имитируем внезапную ошибку (например, упала база данных)
        const error = new Error('База данных временно недоступна');
        next(error); // Передаем ошибку в глобальный обработчик
    });

```
3. В самом низу файла (перед `app.listen`) создай глобальную мидлварь ошибок с 4 аргументами `(err, req, res, next)`.
4. Внутри неё отправь клиенту статус `500` и текст ошибки: `` `Глобальная ошибка сервера: ${err.message}` ``.
