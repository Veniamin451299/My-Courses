# 1. Что мы упустили: Мидлварь `express.json()`

В своем коде для создания книги ты написал:
```javascript
const book = BookService.addBook(req.body);
```

Но по умолчанию Express.js **не умеет** читать JSON, который клиент присылает в теле POST/PUT запросов. Если запустить твой код сейчас, то `req.body` будет равен `undefined`, и сервер упадет с ошибкой.

**Как исправить:** В главном файле сервера (где ты создаешь `app`), в самом верху, перед роутами, нужно обязательно подключить встроенную мидлварь:
```javascript
app.use(express.json()); // Автоматически парсит JSON-тело запроса в req.body
```

_(Это тот самый Body Parser, который мы с тобой мучительно писали руками на чистом Node.js!)_.

# 2. Валидация данных: Защита сервера от "мусора"

Сейчас в твой метод `addBook` клиент может прислать всё что угодно. Например, пустой объект `{}`, или вместо названия книги — число, или вообще прислать деструктивные данные. Сервер послушно запишет это в массив.

В промышленной разработке (и в Express, и в NestJS) действует закон: **Никогда не верь клиенту. Валидируй всё на входе.**

В экосистеме Node.js для этого есть два главных инструмента: библиотеки **Joi** и **Zod**. В современном бэкенде (и особенно в связке с NestJS в будущем) стандартом де-факто стал **Zod**. Он лаконичный, быстрый и проверяет типы данных на лету.

Как устроена валидация через Zod?

Сначала мы описываем **схему** (правила), каким должен быть объект. А затем проверяем `req.body` на соответствие этой схеме.

Давай напишем мидлварь валидации. Для этого нужно установить библиотеку: `npm install zod`.
```javascript
const { z } = require('zod');

// 1. Описываем схему валидации для книги
const createBookSchema = z.object({
  title: z.string({ required_error: "Название книги обязательно" }).min(2, "Слишком короткое название"),
  author: z.string({ required_error: "Автор обязателен" }).min(2, "Имя автора слишком короткое"),
});

// 2. Создаем универсальную мидлварь-валидатор
const validate = (schema) => (req, res, next) => {
  try {
    // parse() проверяет req.body. Если данные плохие — вызовет ошибку.
    schema.parse(req.body); 
    next(); // Все отлично, пропускаем к контроллеру
  } catch (error) {
    // Если Zod нашел ошибки, мы форматируем их и отправляем статус 400 (Bad Request)
    res.status(400).json({
      status: 'fail',
      errors: error.errors.map(err => err.message)
    });
  }
};
```

Как применить это в роутере?

Ты просто вставляешь эту мидлварь перед контроллером:
```javascript
const { createBookSchema, validate } = require('../middleware/validator');

// Валидация сработает ДО того, как запрос попадет в контроллер!
router.post('/', validate(createBookSchema), addBook);
```
