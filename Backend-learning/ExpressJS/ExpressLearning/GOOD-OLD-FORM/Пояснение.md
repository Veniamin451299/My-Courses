# Что делает параметр extended?
Этот параметр определяет, какую библиотеку Express будет использовать внутри себя для превращения сырой текстовой строки формы в удобный JavaScript-объект.

## 1. Вариант extended: false (Используется библиотека querystring)
Это классический, простой парсер, встроенный в сам Node.js. Он умеет парсить только плоские (одноуровневые) объекты.Если форма отправит данные `name=Benjamin&age=25`, он превратит их в:
`javascript{ name: "Benjamin", age: "25" }`

Если ты попытаешься отправить сложную структуру с вложенными объектами или массивами (например, `user[name]=Benjamin&user[age]=25`), этот парсер не поймет вложенность и выдаст странную плоскую строку вроде `{"user[name]": "Benjamin"}`.

## 2. Вариант extended: true (Используется библиотека qs)
Это продвинутый парсер. Сторонняя библиотека qs умеет создавать сложные, глубоко вложенные объекты и массивы из строки запроса.Если отправить ту же строку `user[name]=Benjamin&user[age]=25`, этот парсер создаст красивый вложенный объект:
```javascript
{
  user: {
    name: "Benjamin",
    age: "25"
  }
}
```

## Что будет, если вообще не указать этот параметр?
Если ты напишешь просто `app.use(express.urlencoded())`, современный Express.js выдаст в консоль предупреждение `(Warning): body-parser deprecated undefined extended: provide extended option` 

Сервер продолжит работать (по умолчанию выставится true), но Express настойчиво требует от разработчика явно указать этот параметр, чтобы поведение сервера не изменилось неожиданно при обновлении версий фреймворка.
