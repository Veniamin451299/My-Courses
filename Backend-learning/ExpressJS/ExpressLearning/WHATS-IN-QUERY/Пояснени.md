# Query (Строка запроса) — это ФИЛЬТРАЦИЯ, СОРТИРОВКА и ПОИСК
Они идут в самом конце URL после знака вопроса (?key=value) и являются необязательными. Если их убрать, страница всё равно откроется, просто данные не будут отфильтрованы.

Пример URL: `/search?color=red&size=xl` или `/users?sort=desc`.

Как воспринимает сервер: «Покажи мне все товары, но отфильтруй их так, чтобы остались только красные и размера XL».

Ассоциация: Это как галочки-фильтры в интернет-магазине сбоку страницы.

Ты только что увидел, насколько Express упрощает жизнь. 
Давай вспомним, как мы разбирали Query-параметры в сыром Node.js всего пару задач назад:
```javascript
new URL(req.url, 'http://example.com') 
parseUrl.searchParams.get('results')
```
(причем каждое свойство нужно было доставать руками по отдельности). В Express.js всё это превратилось в элегантное req.query.

Как это будет выглядеть в NestJS?Когда ты перейдешь к NestJS, этот механизм станет еще более декларативным. Вместо того чтобы лезть в объект запроса, ты будешь использовать специальный декоратор @Query(). Например:
```typescript
@Get('search')
search(@Query() query: any) {
  return query; // NestJS сам поймет, что это объект, и вернет JSON
}
```

Или ты сможешь достать конкретный параметр прямо в аргументах функции: search(@Query('results') results: string). Но под капотом NestJS будет использовать ровно тот же req.query из Express!
